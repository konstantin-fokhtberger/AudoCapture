# Аудит AudoCapture и план доведения до рабочего состояния

- Дата: 2026-09-08.
- Статус: аудит текущего кода; архитектурные изменения и оценки ниже предложены, не реализованы.
- Основание: требования пользователя в текущей задаче, исходный код, действующие требования v1.1 и ADR-001/002/003, локальные проверки и документация Apple.
- Границы: приложение не запускалось для записи реальных разговоров; разрешения macOS не изменялись. Исходный код, Package.swift и сценарий упаковки не менялись.

## 1. Вывод

Нативная основа пригодна для развития. Переписывание приложения целиком не обосновано. Однако существующий MVP пока нельзя считать надёжным рекордером для коллег: нет доказанной непрерывности и синхронизации аудио, ошибки захвата не доходят до состояния сессии, сохранение при выходе недостаточно защищено, экспорт зависит от сторонних программ, сборка для распространения отсутствует.

Главный порядок работ: целостность записи -> автономный экспорт -> реальные испытания -> подписанный дистрибутив -> удобство использования. Косметическое обновление интерфейса не закрывает основные риски.

## 2. Требования и допущения

Подтверждено пользователем:

- Запись всего системного звука и микрофона по ручному запуску/остановке.
- Автоматическое сохранение для последующей транскрибации.
- Легковесное приложение для MacBook на Apple Silicon.
- Поддержка macOS последних двух-трёх лет и передача приложения коллегам вне App Store.

Предложения, которые не являются уже принятыми требованиями:

- Минимальная macOS 14 Sonoma; матрица первого выпуска: 14, 15, 26 на arm64. Проверять конкретные поддерживаемые версии, не обещать совместимость с любыми будущими macOS. Sonoma вышла 26 сентября 2023 [S1].
- Основной пользовательский результат: один обычный аудиофайл `recording.m4a` с AAC-LC и сведённым звуком. Раздельные источники сохранять для диагностики и сценариев транскрибации, которым это полезно. Это расширение старого scope, исключавшего сведение.
- Встроенную транскрибацию, сервер, аккаунты и автоматическое обновление не включать в первый выпуск.
- Начальный ориентир длительности - до 4 часов за сессию; это критерий проектирования и испытаний, а не измеренная возможность.
- «Весь звук» означает доступный ОС системный поток без фильтрации по приложениям. Не обещать обход ограничений защищённого контента или политики ОС. Захват микрофона не тождественен точной копии исходящего сетевого аудио Teams/Zoom после их mute, шумоподавления и обработки.

Для реализации ещё понадобится определить целевой сервис транскрибации и его ограничения на размер/длительность файлов. Отсутствие этого выбора не мешает исправлению целостности захвата. Наличие Apple Developer Program и Developer ID пока неизвестно; это зависимость распространения, не аудита.

## 3. Что уже реализовано

- SwiftPM, SwiftUI, AVAudioEngine для микрофона, ScreenCaptureKit для системного аудио; внешних Swift package dependencies нет.
- Параллельный старт разрешённых источников, ручные Start/Stop, выбор микрофона.
- Раздельные WAV: 48 kHz, PCM Int16, mono для микрофона и stereo для системы.
- MP3 через ffmpeg, при его отсутствии через lame; исходные WAV сохраняются.
- Папки сессий, атомарная запись финального JSON, предупреждения о неполном старте.
- Внедрение зависимостей в менеджере и тесты оркестрации.
- Локальная упаковка `.app` с privacy descriptions и ad-hoc подписью.

Важно: текущая `.git` содержит 0 отслеживаемых файлов. Наличие каталога Git пока не обеспечивает воспроизводимую историю проекта. Не выполнялись staging или commit.

Дополнительный риск оркестрации: actor сериализует участки между await, но не весь start/stop целиком. `session` устанавливается после await запуска, а обнуляется до await остановки. UI ограничивает повторные вызовы, но публичный manager не имеет собственного starting/stopping guard. Ввести явный lifecycle на уровне manager и проверить конкурентные вызовы.

## 5. Архитектурные варианты

| Вариант захвата | Плюсы | Минусы / TCO | Решение |
|---|---|---|---|
| ScreenCaptureKit + AVAudioEngine, macOS 14+ | Максимальное повторное использование кода; охват Sonoma; без драйвера | Два clock domain, своя синхронизация и обработка устройств | Рекомендуется для первого выпуска |
| ScreenCaptureKit с захватом микрофона, macOS 15+ | Единый API, меньше capture-компонентов; microphone output добавлен Apple [S2] | Исключает Sonoma; не отменяет проверку форматов, времени, recovery и экспорта | Альтернатива, если коллегам не нужна macOS 14 |
| Две реализации: 14 отдельно, 15+ новый путь | Полный охват и новые API | Две реализации, больше тестов и эксплуатационных различий | Не оправдано для первого выпуска |
| Core Audio process taps | Audio-specific подход, без привязки UI к экранному захвату | Новая реализация и отдельное исследование совместимости/permissions; текущий аудит её не валидировал | Резерв, если SCK не проходит целевые сценарии |
| Виртуальный аудиодрайвер | Гибкая маршрутизация | Установка, настройка, диагностика у коллег, выше TCO | Не соответствует простоте продукта |

Выбор остаётся нативным SwiftUI/SwiftPM. Xcode project допустим, если упрощает подпись, но миграция build system сама по себе не исправляет запись. Backend/DB для одного локального рекордера не нужны. Масштабирование здесь - длительность записи и число установок; ограниченные очереди, потоковая запись и воспроизводимый выпуск важнее распределённой архитектуры.

| Формат | Преимущества | Компромиссы |
|---|---|---|
| M4A / AAC-LC | Нативные API Apple [S3], компактный файл, без внешнего encoder | Сжатие с потерями; требуется проверка выбранным транскрибатором |
| WAV / PCM | Простой анализ и восстановление, без потерь кодека | Большой объём; текущие два источника дают около 1.04 GB/час |
| M4A / ALAC | Без потерь, нативный стек | Размер больше AAC и зависит от сигнала; проверить импорт в сервис |
| MP3 | Широкая совместимость | В текущем коде внешняя зависимость; упаковка encoder увеличивает сопровождение |
| Opus | Эффективен для речи | Дополнительная проверка контейнера, кодека и транскрибатора; нет преимущества достаточного для нового стека в MVP |

Предложение: временные сегменты PCM/CAF с данными времени -> сведение и AAC-LC -> временный выходной файл -> проверка декодирования -> атомарная публикация `recording.m4a`. Исходники удалять только после успешной проверки и согласно явной политике хранения. Раздельные компактные дорожки можно сохранить настройкой. Сначала исправить синхронизацию: простое сложение двух файлов по нулевой позиции неверно.

Ориентир для общего AAC: 128 kbit/s mono для речи или 192 kbit/s stereo при необходимости сохранить системное stereo. Это примерно 57.6/86.4 MB за час без небольших накладных расходов контейнера. Текущий PCM: `48000 × 2 bytes × (1 + 2 channels) × 3600 = 1 036 800 000 bytes/hour`; два MP3 по 192 kbit/s добавляют 172.8 MB/час. Хранение всех текущих файлов - около 1.21 GB/час. Нужно учитывать временный запас диска и рост файлов до многогигабайтных размеров; для длительных сессий CAF/сегменты предпочтительнее зависимости от пределов WAV.

Сведение: запас по уровню/limiter, контроль clipping; нельзя гарантировать устранение акустического дубля, когда системный звук из динамиков попадает в микрофон. Гарнитура уменьшает эту проблему. AEC следует добавлять только после измерения качества: это отдельная сложная работа, а не бесплатное свойство ScreenCaptureKit.

Предварительно 13.5-25 рабочих дней плюс внешние ожидания; больший объём возможен при существенных проблемах Bluetooth или синхронизации. После W1 оценку пересчитать по фактическим результатам. Переписывание backend захвата, встроенная транскрибация, гарантированный AEC и автообновление в диапазон не включены.

## 7. Критерии готовности и тестовая матрица

Все численные границы ниже - предлагаемые acceptance targets, пока не измеренные свойства приложения.

1. На каждой macOS 14/15/26: установка из скачанного ZIP/DMG на Apple Silicon, первый запуск, отказ/выдача/отзыв разрешений, повторный запуск и обновление версии.
2. Реальные источники: встроенный микрофон, USB, Bluetooth/AirPods; встроенный/проводной/Bluetooth выход. Матрица устройств покрывается риск-ориентированно на доступных Mac; хотя бы built-in и Bluetooth на каждой OS. Не подменять это запуском новой OS с deployment target 14.
3. Системный звук: браузер, Zoom/Teams, одновременно два приложения, фоновые/минимизированные окна, внешний дисплей и его отключение. Проверить реально слышимый звук, а не только наличие WAV.
4. Известные импульсы на обоих источниках: старт, середина, конец 30-минутной и 2-часовой записи. Предложение: остаточное рассогласование <=100 ms, без необъяснённого накопления drift; отсутствие аудио должно отличаться от здоровой тишины по состоянию pipeline.
5. 100 циклов Start/Stop; двойные команды, два экземпляра, одинаковый timestamp; отдельные каталоги, отсутствие перезаписи и потери хвоста.
6. Quit во время starting/recording/processing, включая экспорт >5 секунд; обычный выход сохраняет результат. Для force quit/power loss - обнаружение incomplete и восстановление опубликованных сегментов, а не обещание сохранности ещё не записанных буферов. Предложение: checkpoint/segment не реже 5 секунд; фактическую границу потери измерить.
7. Диск заполнен, папка недоступна, ошибка writer/encoder; исходники остаются, UI сообщает о неполном результате. Ошибка экспорта не уничтожает записанный материал.
8. Отключение гарнитуры/смена sample rate/выхода, сон и wake: явное завершение или контролируемое продолжение с отметкой разрыва. Не обещать запись при реальном сне Mac; отдельно определить предотвращение idle sleep только во время активной записи.
9. Экспорт читается системным декодером и выбранным транскрибатором. Проверены обе стороны разговора, пересечения речи, clipping и акустический дубль. Одна track с двумя источниками не обеспечивает diarization по участникам.
10. 4 часа: читаемый результат, отсутствие необъяснённых пропусков и роста памяти. Предлагаемые бюджеты: idle CPU <1% одного ядра, capture в среднем <=10% одного ядра на базовом M1, RSS <=150 MB, release `.app` <=30 MB. Замерять также post-processing отдельно; отклонение обсуждать по данным, не превращать бюджет в неподтверждённое обещание.

Best practice для этого продукта: bounded realtime path, timestamp-based timeline, сохранение исходников до верификации экспорта, явные неполные состояния и приёмка подписанного release на другом Mac. Подпись Developer ID и notarization - стандартный путь распространения вне App Store [S4]; это не публикация в App Store.
