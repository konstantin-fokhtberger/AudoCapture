# Итерация I3: один нативный M4A

## Реализовано
- Общий host-clock для microphone и system audio; leading silence, паузы и обрезка перекрытий в PCM. Допуск 5 ms, большие разрывы начинают новый сегмент после drain converter.
- NativeM4AExporter: блочное stereo-сведение и AAC 48 kHz/192 kbit/s, полное декодирование результата до публикации. Микрофон попадает в оба канала; stereo системы сохраняется.
- Итоговый файл `dd-MM-yyyy HH-mm.m4a` в Documents/Recordings, имя по локальному времени старта. Коллизии получают `(2)` без перезаписи. В UI время содержит двоеточие.
- Внешний ProcessMP3Encoder и subprocess-путь удалены. Старые optional MP3-поля JSON оставлены исключительно для совместимости metadata.
- Рабочие дорожки/metadata перенесены в `.sessions/<UUID>`. Успешно экспортированные PCM удаляются после проверки файла и сохранения metadata. Ошибка финализации источника сохраняет этот исходник и даёт partial capture.
- Ошибки экспорта оставляют PCM и кнопку Retry Saving; повторное сохранение использует исходную дату и не запускает capture. Retry последнего экспорта доступен до перезапуска приложения; crash recovery отложен.
- Capture status и export status независимы: успешный M4A с одной доступной дорожкой не объявляется полной записью двух источников.

## Проверка
- 46 тестов в 10 suites, 0 failures; 5.484 s тестового времени. Сборка core, app и smoke executable прошла; compiler warnings/errors не обнаружены.
- Smoke check: `Smoke checks passed.`
- Полный Xcode/Swift 6.3.3, macOS 26.6.2, scratch build `/tmp/audocapture-iteration3-build`; журнал `/tmp/audocapture-i3-tests.log`.
- Проверяется реальный AVAudioFile AAC encoder/decoder, а не только mock. Пустой PCM не превращается в успешный файл тишины; неверная ожидаемая длительность отклоняется повторной проверкой.
- Проверены локальные ссылки новых документов и отсутствие trailing whitespace изменённых Swift-файлов. Baseline сравнения I3 сохранён в `/tmp/audocapture-i3-review.diff`.
- Репозиторий пока без tracked baseline; staging/commit в этой итерации не выполнялись, это остаётся B10.

Новые сценарии: два разных источника и отдельные stereo-частоты, длительность с хвостовой тишиной, отсутствие перекрёстной подмены каналов, коллизия имён и неизменность первого файла, неверный PCM, отмена без публикации, временные паузы и перекрытия, локальная дата с переходом через UTC-полночь, ошибка экспорта -> retry -> удаление PCM без повторного capture. Старые lifecycle/conversion/permissions/quit проверки сохранены.

## Ограничения и следующие работы
- Реальные записи и прослушивание с микрофоном/гарнитурой ещё не проводились. Базовый mix проверен синтетически; длительная синхронизация и уровни остаются B14/B11.
- UI пока сохраняет прежнюю структуру; его упрощение, таймер и обновление разрешений - B08. Реакция на устройство/сон - B09.
- macOS 14/15/26, другой Mac, Developer ID/notarization ещё не проверены. Deployment/build hygiene - B10, распространение - B12-B13.
- Ограничения диска, sync I/O, fixed gain, 24 h validation limit и hard-link publication описаны в [ADR-005](../02-decisions/2026-09-08_adr-005_single-native-m4a.md).
- Повторный экспорт в текущем процессе не заменяет crash recovery; исходники после аварийного завершения не восстанавливаются автоматически.
