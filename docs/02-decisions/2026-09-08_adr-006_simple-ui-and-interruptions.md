# ADR-006: компактное управление и остановка при изменении среды

## Status
accepted, 2026-09-08. Код I4 реализован; аппаратные критерии B09 остаются открытыми.

## Context
Первый выпуск должен запускаться и использоваться с минимумом действий. После изменения аудиоконфигурации приложение не должно продолжать показывать нормальную запись. Бесшовный reconnect и продолжение после сна не входят в текущий scope.

## Decision
- Сохранить существующие ViewModel и manager. Главное окно: одна переключаемая кнопка Start/Stop, таймер, выбранный микрофон, фактически активные источники, результат и Finder. Во время starting/processing основная кнопка заблокирована.
- Таймер использует host-clock начала capture из startup report, а не время нажатия кнопки/окончания permissions. Обновляется раз в секунду только в recording, останавливается на Stop; после экспорта показывает итоговую metadata duration.
- Обновлять разрешения и перечень микрофонов при активации приложения и пробуждении; выбор устройства не меняется в активной сессии. Отдельные Refresh-кнопки удалены.
- RecordingEnvironmentMonitor подписывается на NSWorkspace willSleep/didWake, активацию приложения, изменение дисплеев и Core Audio devices/default input/default output. При изменении аудиоокружения используется консервативный Stop, в том числе при подключении другого аудиоустройства. Ошибка установки Core Audio listener видна как постоянное предупреждение.
- AVAudioEngineConfigurationChange собственного микрофонного engine замораживает приём буферов и сообщает прерывание. Это не ошибка записи PCM: уже записанный материал остаётся пригоден для drain/finalize/export. Teardown не выполняется внутри notification callback.
- При interruption в recording ViewModel синхронно переходит в processing и запускает обычный Stop без автоматического Finder. Повторные события игнорируются. Причина записывается в metadata и результат становится partial.
- При interruption в starting отменяется текущая Task. Если источник не поддержал отмену и всё же запустился, вслед за успешным startup выполняется Stop. После wake нет автоматического старта новой записи.
- Локальный Run вызывает существующий сборщик bundle через тонкий скрипт. Перезапуск запрашивает обычный Quit и ждёт безопасного завершения; force kill не используется.

## Alternatives considered
| Вариант | Компромисс |
|---|---|
| Polling устройств каждую секунду | Лишняя постоянная работа; OS notifications точнее выражают нужные события |
| Бесшовный reconnect | Требует нового lifecycle маршрутов и дополнительной синхронизации; отложен |
| Игнорирование новых устройств, отслеживание только выбранного | Меньше ложных остановок, сложнее охват маршрутов; вернуться после pilot, если консервативная политика мешает |
| Принудительное завершение через timeout при Run | Может оборвать M4A; выбран обычный Quit, ожидание без kill |

## Consequences
- Без новых зависимостей, driver, event bus, DB или фонового polling устройств. Подписки снимаются при освобождении monitor.
- Таймер является индикатором прошедшего времени, не измерителем непрерывности входящих буферов. Тишина/потеря потока без OS-события требуют аппаратной проверки; универсальный watchdog пока не вводится.
- WillSleep инициирует остановку, но async Stop/экспорт могут продолжиться после пробуждения. Завершение экспорта до принудительного сна/закрытия крышки не гарантируется; синхронной блокировки UI ради задержки сна нет. Power loss/crash recovery остаются D03.
- Отключение USB/Bluetooth, изменение дисплея/формата и физический сон необходимо проверить в B09/B11. Unit-тесты не являются подтверждением реального поведения HAL/ScreenCaptureKit.
