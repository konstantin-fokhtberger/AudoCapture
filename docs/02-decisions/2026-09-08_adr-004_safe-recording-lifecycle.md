# ADR-004: явный жизненный цикл и безопасное закрытие записи

## Status
accepted - реализовано в итерации I2 в рамках разрешённой итерационной доработки.

## Context
Actor не защищал Start/Stop целиком через await. Буферы могли ошибочно завершать converter, runtime errors не доходили до UI, а Quit разрешался по истечении пяти секунд независимо от завершения записи.

## Decision
- Один простой enum lifecycle в RecordingManager; переход до первого await, возврат в idle при завершении/ошибке. Session ID отсекает поздние события прошлой записи.
- UUID в имени внутренней папки, чтобы cleanup новой сессии не затрагивал старую. Это не имя итогового M4A.
- Общий внутренний CaptureBufferWriter для двух источников: одна serial queue защищает converter/close, без неограниченного накопления аудиобуферов. Он сообщает первую ошибку через callback и всегда закрывает PCM writer.
- При Stop converter получает endOfStream и дренируется; источники прекращают выдачу буферов до финализации. Источник с неуспешным Stop не передаётся encoder автоматически.
- ViewModel хранит выполняемую Task. Quit ждёт её, при starting отменяет ожидание; timeout не считается разрешением завершить приложение.
- Неполная запись/экспорт обозначается partial. Неизвестные frame metrics и неприменимая разница длительностей представлены optional values.
- Ожидание privacy response отменяемо, без фиктивного трёхсекундного timeout; системный диалог принадлежит macOS и может остаться видимым.

## Alternatives considered
- Считать блокировку кнопки достаточной: оставляет публичный manager некорректным.
- Закрывать через фиксированный timeout: теряет данные при медленной обработке.
- Внедрить event bus, отдельный service framework, ring buffer или custom executor: не требуется для исправления текущих инвариантов.

## Consequences
- Сохранена существующая архитектура ScreenCaptureKit + AVAudioEngine и fallback ADR-003.
- Ошибка источника в приложении инициирует обычную безопасную остановку через ViewModel; headless consumer manager должен самостоятельно вызвать Stop по failure callback.
- Синхронный I/O остаётся ограничением до профилирования B11; очередь не накапливает неограниченное число копий буферов.
- Зависший внешний MP3 encoder пока способен задержать Quit: данные не обрываются принудительным выходом. Удаление subprocess path запланировано в I3/B06.
- Сведение, единый M4A, имя итогового файла, recovery после force quit и переключение устройств этим ADR не реализуются.
