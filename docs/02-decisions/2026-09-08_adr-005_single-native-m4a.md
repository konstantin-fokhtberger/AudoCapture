# ADR-005: один датированный M4A с общей временной шкалой

## Status
accepted, 2026-09-08. Реализация явно запрошенного пользователем единого файла; заменяет прежний путь раздельных итоговых MP3. Исторические ADR и требования v1 сохранены.

## Context
Простой локальный recorder для Apple Silicon должен автоматически сохранять микрофон и весь системный звук в один файл для последующей транскрибации. Не требуется внешний encoder, сервер, БД или адаптивный DSP. Целевая матрица macOS 14/15/26 остаётся непроверенной аппаратно.

## Decision
1. ScreenCaptureKit и AVAudioEngine сохраняются. Оба источника получают общий start host-clock. Время microphone tap переводится из host units; PTS системы переводится из SCStream.synchronizationClock в CMClockGetHostTimeClock.
2. CaptureBufferWriter формирует временную шкалу каждого PCM: тишина до первого буфера и в пропусках, обрезка перекрытий. Отклонения до 5 ms сглаживаются продолжением текущего сегмента; больше - drain и новый сегмент. Это простая коррекция разрывов, без adaptive resampling.
3. После Stop нативный AVAudioFile сводит 48 kHz PCM блоками 4096 frames и кодирует AAC 192 kbit/s, stereo, в M4A. Mono microphone добавляется в оба канала, stereo системы сохраняется. Gain каждого входа = 0.9 / число входов. Пиковая сумма до AAC ограничена 0.9; посткодековые пики могут отличаться.
4. Длительность результата не короче времени start -> Stop по монотонным часам и самой длинной дорожки. Пропуски и более короткие дорожки дополнены тишиной. Нет автоматической нормализации или AEC.
5. Итог: `~/Documents/Recordings/dd-MM-yyyy HH-mm.m4a`. Имя и локальный часовой пояс фиксируются при старте capture после permissions; UI показывает дату и HH:mm. Служебные PCM и JSON находятся в `.sessions/<UUID>`.
6. AAC сначала закрывается в autoreleasepool (совместимо с macOS 14 без AVAudioFile.close), затем полностью декодируется для проверки codec/channels/rate/duration/finite samples. Готовый файл публикуется hard link в том же каталоге: атомарно, без перезаписи; при совпадении суффикс `(2)`, `(3)` и далее. Временная ссылка удаляется.
7. Удаляются только успешно финализированные исходники, участвовавшие в проверенном экспорте, и только после записи metadata о готовом результате. Нефинализированный источник сохраняется. Сбой экспорта или первичного metadata write оставляет исходники и возможность Retry Saving без capture.
8. Retry ограничен последним неудачным экспортом в текущем процессе. Уже опубликованный файл повторно не кодируется при повторной попытке записи metadata, если он существует и повторно прошёл полное декодирование/проверку длительности. Восстановление после перезапуска/аварии отложено.

## Alternatives considered
| Вариант | Компромисс |
|---|---|
| ffmpeg/lame | Дополнительная установка, subprocess lifecycle и упаковка; не нужны для системного AAC |
| Real-time AAC mix | Меньше временного диска, сложнее синхронизация и восстановление; не нужен для первого запуска |
| AVAudioEngine offline graph | Дополнительный graph/lifecycle для двух уже нормализованных дорожек; прямое блочное сведение проще |
| Adaptive drift correction/AEC | Полезны только после измерений, увеличивают DSP и тестовую матрицу; отложены |

## Consequences
- Один пользовательский аудиофайл, отсутствуют внешние runtime encoder dependencies. Память сведения ограничена размером блоков; время экспорта и повторного декодирования линейно длительности.
- PCM16 48 kHz mono + stereo требуют около 1.04 GB/час временного диска; M4A при 192 kbit/s ориентировочно 86.4 MB/час без учёта контейнера. Это расчёт, не измерение pilot.
- Фиксированный gain оставляет запас, но не выравнивает тихий микрофон относительно громкой системы. Гарнитура и одновременная речь проверяются в B11.
- Границы валидации: длительность и timestamps до 24 h. Записи такой длины не заявлены проверенными. Синхронное заполнение длительных пауз может задерживать capture callback; сон и I/O performance остаются B09/B11.
- Hard links рассчитаны на локальное хранилище с их поддержкой (типично APFS). Для неподдерживающей файловой системы экспорт возвращает ошибку, исходники остаются; выбор внешней папки пока не входит в UI.
- Crash recovery и бесшовное продолжение после сна не заявлены.
